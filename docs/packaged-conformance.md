# Packaged HTTP conformance

`hap-conformance packaged` exercises the shipped HTTP interface: exact handshake identity, successful Result against the shipped schema, ordered events, unchanged duplicate-task replay, accepted cancellation, and an active deadline. It performs no source tests and never fetches remote schemas. Fixture inputs explicitly declare their result schema target and input identities. The bounded delay extension is honored only by an agent's fixture profile.

Runner's generic `oci/verify@v1` resolves the supplied immutable deployment image to the selected Linux manifest and runtime config, verifies both pulled identities, and extracts its definition and schema files. The subject has no external network; the verifier shares only that isolated network namespace. Both are read-only except bounded temporary/output storage, without signer or host credential mounts. The host creates `runner-oci-verification/v1`, binding deployment image, platform manifest/config, verifier image, fixtures, definition and test result digests.

`sign-packaged` consumes that typed verification artifact and an approved release policy. It derives the subject digest from Runner's record; no supplied build digest is accepted. The policy allowlists verifier image digests and exact agent/interface/scenario and execution-recipe digests. Subject arguments, fixture environment, extracted paths and verifier arguments are all bound. Every required check must pass before the separate signer creates detached descriptor and interface receipts. The signer uses approved file handles and is never passed into either container.

The v2 signed context uses `dev.hap.agent-conformance-context/v2` and suite `hap-0.2-packaged-agent/v1`. It binds platform, leaf manifest, runtime configuration, verifier artifact, fixture archive, execution recipe and host verification record in addition to the existing agent/build identity. The Receipts envelope remains unchanged.

`gate-deployment` accepts Runner's typed image and detached evidence inputs, verifies trusted signatures for the exact image/platform/deployed interface, and rejects legacy source-test evidence. Legacy v1 evidence remains readable for older reporters; it cannot pass deployment admission.

Release order: publish/pin the private Receipts Go module; release Protocol CLI/module and the conformance image through `.local-ci/conformance.yaml`; approve the resulting immutable verifier digest and public signer keys in the consumer repository; update its Runner lock from an actual Runner release manifest. Preparation and static validation do not publish packages, provision signers, authorize deployment or prove production health. The current empty consumer allowlists intentionally block signing until approved values exist.
